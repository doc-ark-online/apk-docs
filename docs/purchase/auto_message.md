# 游戏自动化消息

自动化消息用于游戏在业务发生时，向本游戏用户发送站内信和 Push。适用互动提醒、好友私信、福利活动和系统通知。

开发者先在后台开通能力、配置消息模板。游戏在合适场景通过联运 SDK 确认用户已授权对应类型，再由游戏服务端创建发送任务，传入模板 ID 和占位内容。平台按模板生成最终文案，同时下发站内信与 Push，并在任务结束后把发送结果回调到开通时填写的地址。

平台负责站内信和 Push 的下发。游戏内加次数、发道具由各游戏自行实现。回调中的成功数表示平台侧已发送成功，不代表用户已实际接收。用户未授权对应消息类型时，发送会被拒绝。

## 1. 开通自动化消息

上传游戏后，进入 **游戏运营 → 自动化消息**，先开通。提交后需等待审核通过，通过后才能创建模板、创建发送任务。

1. **模板类型**：勾选本游戏要用的类型。可选：互动通知提醒、好友私信提醒、福利活动提醒、系统通知提醒。后面创建模板时，只能选这里已开通的类型。
2. **结果回调地址**：用来接收消息任务的发送结果。地址要求和返回格式见 [自动化消息回调地址配置说明](./auto_message_callback.md)。

## 2. 创建消息模板

开通通过后，在同一入口创建消息模板。提交后需等待审核通过，模板生效后才能用于创建发送任务。

1. **标题 / 正文**可以写入占位符，格式为 `${xxx}`。例如标题写成「`${nick}`，你有一条新的活动提醒」，创建消息任务时再传入 `nick` 的实际内容。
2. 创建成功后生成 **模板 ID**。创建消息任务时传入该 ID。模板须已生效，且类型在本游戏已开通的消息权限内。同一模板会同时下发站内信和 Push。

## 3. 获取用户通知权限

用户未授权对应消息类型时，发送会被拒绝。请在 SDK 初始化成功后，在支持该能力的沙盒环境中接入。这里的推送权限是游戏消息分类授权，不是 Android 系统通知权限。授权弹窗由乐园拉起。

可查询或申请的类型，与开通时勾选的模板类型对应：互动通知、好友私信、福利活动、游戏内系统消息。调用时只传入本游戏已配置的类型。

1. **查询推送权限**：查看用户是否已允许接收对应类型，不展示授权弹窗。
2. **申请推送权限**：尚未授权时调用，由乐园拉起授权弹窗。申请结束后直接使用回调里的授权状态，无需再次查询。回调成功不代表所申请的类型全部已授权。

见 [游戏推送权限（沙盒环境）](../SDK/client_access.md#push-permission)。

## 4. 创建消息发送任务

游戏服务端用模板 ID、占位符内容和收件人创建任务。接口立即返回任务 ID，发送是否成功等回调。

见 [创建消息发送任务](./create_message_task.md)。
